## Quick Reference: Where to Edit

| Task | Where to Edit |
|---|---|
| Add API route | `vm_builder/api/routes/` (new module) + register in `app.py` |
| Add CLI command | `vm_builder/cli_atomic/` (registration) + `vm_builder/commands/` (impl) |
| Add service method | `vm_builder/core/{svc}_service_parts/` (new part file) + facade re-export in `core/{svc}_service.py` |
| Add new core service | `vm_builder/core/` (facade) + `_parts/` subpackage + `api/deps.py` (DI) |
| Add app to templates | `vm-builder-templates/apps/{app}/` with `.idi-meta.yaml` sidecar |
| Change VM schema | `vm_builder/schema_parts/` |
| Add template sidecar detector | `vm_builder/template_sidecars/` (new module) |

## 3. API Route Map

All endpoints across route files, traced to their service and atomic parts.

### Router Registration Order (app.py)

```python
1. health.router                   # /api/v1
2. init.router                     # /api/v1/init
3. hypervisor.router               # /api/v1
4. vm_health.router                # /api/v1
5. vm_apps.router                  # /api/v1
6. vm_config.router                # /api/v1
7. vm.router                       # /api/v1
8. registry.router                 # /api/v1/registry
9. schema_routes.router            # /api/v1/schema
10. webhook.router                  # /api/v1/webhook
11. storage.router                  # /api/v1/storage
```

### Middleware Stack

- `CORSMiddleware` — Allows `http://localhost:5173`, all methods/headers
- `AuditMiddleware` — Logs all API requests, redacts secrets, skips health/docs/static

### Exception Handling

- `VmBuilderError` → JSON 400 response with error details
- Unhandled exceptions → JSON 500 with request ID for correlation

### SPA Serving

- `_SPA_CANDIDATES`: probes `vm-builder-web/dist` (dev) and `/app/web/dist` (container)
- `StaticFiles` mount at `/` for static assets
- Fallback `index.html` for client-side routing

### Lifespan Events (startup)

- Load config from BWS (graceful if missing on first boot).
- Sync enterprise repo (clone or pull) if config loaded.
- Auto-generate registry when templates are available.

## Architectural Patterns

### _ModuleProxy + _wire() Pattern

Every service facade uses this DI pattern for testability:

```python
class _ModuleProxy:
    def __init__(self, target_name: str) -> None:
        self._target_name = target_name
    def __getattr__(self, attr: str):
        return getattr(globals()[self._target_name], attr)

def _wire(module, **deps: str) -> None:
    for attr, target_name in deps.items():
        setattr(module, attr, _ModuleProxy(target_name))
```

**Used in 6 facade files:** `core/app_install_service.py`, `core/health_service.py`, `core/hypervisor_service.py`, `core/init_service.py`, `core/repo_service.py`
  + 1 more

**Usage examples:**

```python
_wire(update_inventory_apps_part, bws="bws")  # from core/app_install_service.py
_wire(uninstall_app_part, bws="bws")  # from core/app_install_service.py
_wire(trigger_install_workflow_part, subprocess="subprocess", time="time", json="json")  # from core/app_install_service.py
_wire(trigger_config_workflow_part, subprocess="subprocess", time="time")  # from core/app_install_service.py
_wire(get_latest_run_url_part, subprocess="subprocess", json="json")  # from core/app_install_service.py
```
